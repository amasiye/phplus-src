# Production Source Maps

Every manifest-owned output has a version 1 JSON source map beneath:

~~~text
<output>/.ppphp/source-maps/<output-relative-path>.map.json
~~~

Compiled `.ppphp` uses the byte-accurate map produced by source-edit lowering. Copied `.php` uses one identity segment. Generated PHP does not receive a browser-style source-map comment.

## Format

Each map records the project-relative source path, output-root-relative generated path, SHA-256 source and generated hashes, generated byte length, and deterministically ordered segments. Paths use forward slashes and never contain an absolute project or transaction path.

~~~json
{
    "formatVersion": 1,
    "source": "src/Core/Person.ppphp",
    "generated": "Core/Person.php",
    "sourceHash": "sha256:...",
    "generatedHash": "sha256:...",
    "generatedLength": 824,
    "segments": [
        {
            "generatedStart": 0,
            "generatedEnd": 32,
            "originalStart": 0,
            "originalEnd": 6,
            "ownerStart": 0,
            "ownerEnd": 6
        }
    ]
}
~~~

Offsets are zero-based UTF-8 byte offsets and ranges are half-open. `ownerStart` and `ownerEnd` are optional; when present they identify the original span responsible for generated text such as strict-type insertion or lowered control flow.

Before commit, the compiler verifies the map path is inside `.ppphp/source-maps/`, its identity and hashes match the manifest entry and output, its generated length matches the output bytes, and its segments are ordered and in range. Partial builds also validate every preserved manifest-owned map before merging.

Production maps support deployment diagnostics such as `php -l` line remapping. Editor definition and semantic-token commands do not depend on them; those commands work directly from project source and the current unsaved buffer.
