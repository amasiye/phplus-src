# ++PHP 2026.3.1-rc-1

`2026.3.1-rc-1` is the prepared first MVP Release Candidate. It is a prerelease, is not yet published during Stage 14A, and is not Stable.

## Why ++PHP

++PHP adds explicit compile-time types and erasable language features to PHP-shaped source, then emits ordinary PHP 8.4. Existing `.php` and selected `.ppphp` files coexist in one project and one generated runtime tree.

## Installation

After Stage 14B publishes the candidate, install its exact identity in a Composer project:

```bash
composer require --dev atatusoft-ltd/ppphp-src:2026.3.1-rc-1
```

The unqualified command `composer require --dev atatusoft-ltd/ppphp-src` remains reserved for the default Stable channel. It does not normally select this RC.

## First project

```bash
vendor/bin/ppphp init
vendor/bin/ppphp composer:configure --dry-run
vendor/bin/ppphp composer:configure
vendor/bin/ppphp check
vendor/bin/ppphp build
php -l build/ppphp/index.php
php build/ppphp/index.php
```

See [Getting Started](../getting-started.md) for a complete walkthrough and [Migrating From PHP](../migrating-from-php.md) for incremental adoption.

## MVP features

- Explicit mutable and readonly locals and typed loop declarations.
- Strict parameter, property, return, project-call, member, property, and nullability checks.
- Union, intersection, DNF, erased generic, typed-list, and typed-map contracts.
- Checked errors and expression-oriented `when`.
- Compiler-owned type flow, Composer/dependency declarations, PHP 8.4 signatures, and stable diagnostics.
- Content-addressed compiler evidence, atomic mixed builds, source maps, and Composer runtime projection.

## Mixed projects and deployment

Ordinary `.php` remains valid source and is copied byte-for-byte into the configured build tree. `.ppphp` is analyzed and lowered to ordinary PHP. A complete pathless build owns `build/ppphp`; deploy and execute that generated tree with the project's Composer metadata and dependencies. Do not run `.ppphp` source directly.

## Analyzer behavior

Compiler-owned analysis defines ++PHP semantics and all required MVP and boundary capabilities. Native `ppphp check` and `ppphp build` also retain the pinned PHPStan supplemental phase for deep ordinary-PHP bodies, generator-specific flow, and established backend evidence. Browser protocol version 2 is an internal process-free checking protocol, not a supported browser build product.

## Supported versions

- Compiler host: PHP `^8.4`.
- Generated output target: PHP 8.4.
- Package manager: Composer 2; the release workflow pins Composer 2.10.3.
- Compiler process memory limit: at least 512 MiB.

## Known limitations

- Generated output targets PHP 8.4.
- Native check and build retain PHPStan.
- Deep ordinary-PHP body analysis remains supplemental.
- Generator-specific compiler-owned flow is not complete.
- Browser compiler analysis is an internal protocol, not a supported browser build product.
- No formatter or standalone LSP ships with this compiler repository.
- Records, postfix list types, Native Type Members, and attribute factory expressions are post-MVP features.
- RC behavior may still change before Stable.
- No public compiler plugin API exists; internal PHP classes are not an MVP extension contract.

## Upgrading from `dev-2026.3.1`

The language and generated-output contracts remain those completed through Stage 13D. Rebuild the complete output tree because the public version, internal build identity, schema identity, cache keys, and manifests change. The canonical compiler namespace is `Atatusoft\Ppphp`; integrations that referenced internal classes must update, while the supported `ppphp` CLI is unchanged.

## Security and feedback

Report vulnerabilities privately as described in [SECURITY.md](../../SECURITY.md). Report non-sensitive RC defects through [GitHub Issues](https://github.com/atatusoft-ltd/ppphp-src/issues), including a minimal reproduction and the exact compiler version.
